# VBAマクロ調査記録（作業確認表 / 認証印）

Excelマクロをfocus-opsに移植できるか検討する過程で、`作業表入出力用マクロ_2026年度.xlsm` と `2026年度_個人作業確認表_Ver29.xlsm` のVBAソースを抽出した際の記録。

## 背景

- `作業表入出力用マクロ_2026年度.xlsm` はVBAプロジェクトが保護されておらず、通常の手順で読めた
- `2026年度_個人作業確認表_Ver29.xlsm` はVBE（Alt+F11）を開こうとするとパスワードを求められ、通常の手順ではソースを閲覧できない状態だった

## 抽出方法（VBEを経由しない直接解析）

`.xlsm` は ZIP + `xl/vbaProject.bin`（OLE2/CFBF複合バイナリ）という構造で、モジュールのソースコードは独自圧縮（MS-OVBA仕様）で格納されている。

VBEの「プロジェクトを表示する前にパスワードを求める」設定は **VBE UI側のチェックに過ぎず、モジュールのソースコード自体（圧縮ストリーム）は暗号化されていない**。そのため以下の手順でVBEのロックを経由せずソースを取り出せた。

1. `.xlsm` を ZIP として展開し、`xl/vbaProject.bin` を取り出す
2. CFBF（OLE2複合ファイル）を自前でパースし、`dir` ストリームおよび各モジュールのストリームを特定する
3. モジュールストリーム内で、展開結果が `Attribute VB_Name` から始まる位置を総当たりで探索し、その位置から MS-OVBA 圧縮アルゴリズム（LZ77類似の独自圧縮）で展開する
4. 展開結果はVBAソースコードの平文（Shift-JIS）

この方法は `oletools` 等の外部ツールを使わず、Pythonの標準ライブラリのみで実装した（ネットワーク制限で外部ツールを導入できなかったため）。

**注意**: VBAプロジェクトのパスワード保護は一般に強度が低く、同種のバイパス手法や専用ツールが広く出回っている。ここで使えた／使えなかったという結果は、暗号強度の高さを意味しない。

## わかったこと

- `2026年度_個人作業確認表_Ver29.xlsm` の `グローバル変数` モジュールに、以下がハードコードされた `Public Const` として定義されていた
  - シート保護解除用パスワード（`protectPSW`）
  - `認証*.xlsx` 形式の認証印ファイルを開くための共通マスターパスワード（`ninshoPSW`）
- 値そのものはこのドキュメントに記載しない（後述の理由）。VBAソースの該当行を直接参照すること
- 認証印の「押印」は画像ではなく、承認者名・日付をもとにVBAがその場で描画する図形（楕円＋直線2本＋テキストボックス3つ）だった
- 認証チェックは、共通マスターパスワードで認証テーブルブックを開いた上で、テーブル内の「パスワード」列とユーザー入力を**平文文字列比較**する方式だった（ハッシュ化なし）

## 値をこのドキュメントに書かなかった理由

`ninshoPSW` は特定ファイル固有ではなく、命名規則 `認証*.xlsx` に合致する組織内の認証印ファイル全般に共通するマスターキーとみられる。このリポジトリはGit管理下にあり、値をここに書くとコミット履歴に恒久的に残る。実際の値が必要な場合は、`2026年度_個人作業確認表_Ver29.xlsm` の `グローバル変数` モジュールを直接参照すること。

## 結論：認証印（押印）機能はfocus-opsに移植しない

focus-opsはビルドシステムなし・サーバーなしの静的サイトであり、ブラウザで完結する。この構成でマスターパスワードを使う処理を実装すると、`ninshoPSW` を**ブラウザ側JSソースに平文で埋め込んで配布する**ことになる。

- ブラウザで動く以上、値は実行時に必ずJSのメモリ上に平文で存在し、DevToolsで誰でも読める
- VBEロックという多少の障壁すら失われ、露出の容易さが大きく上がる
- このキーは組織内の認証印ファイル全般に影響するため、focus-opsを開ける人全員に組織の認証基盤の鍵を配ることになりかねない

このリスクを踏まえ、押印機能はfocus-opsに実装せず、従来どおりExcel上でVBAマクロを手動実行する運用のままとする方針とした。

一方で「作業確認表の勤務データ・年月ヘッダーへの書き込み」は、マスターパスワードや認証テーブルに依存しないため、focus-ops側の機能として一度実装した（`js/workSheets/excelImport.js`）。その後、この機能自体を廃止する判断となり、コードは削除済み。
